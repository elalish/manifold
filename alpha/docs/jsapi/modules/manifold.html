    Interfaces

    ExecutionContext

    Observe and control a long-running Manifold evaluation. Attach to a Manifold via Manifold.withContext(); the next eager op invoked on the result (status(), one of the refine* family, hull(), or minkowskiSum() / minkowskiDifference()) snapshots the ctx and reports progress / observes cancellation through it. Deferred ops (Boolean, transforms, batch ops) ignore any attached ctx. Safe to read/write from any thread/worker.

    Cancellation is permanent for a Manifold: once cancelled and detected, the Manifold's status becomes 'Cancelled' and stays 'Cancelled'.

    Basics

    CrossSection

    Two-dimensional cross sections guaranteed to be without self-intersections, or overlaps between polygons (from construction onwards). Polygon clipping (boolean) and offsetting use Manifold's own robust floating-point predicates.

    Manifold

    This library's internal representation of an oriented, 2-manifold, triangle mesh - a simple boundary-representation of a solid object. Use this class to store and operate on solids, and use MeshGL for input and output, or potentially Mesh if only basic geometry is required.

    In addition to storing geometric data, a Manifold can also store an arbitrary number of vertex properties. These could be anything, e.g. normals, UV coordinates, colors, etc, but this library is completely agnostic. All properties are merely float values indexed by channel number. It is up to the user to associate channel numbers with meaning.

    Manifold allows vertex properties to be shared for efficient storage, or to have multiple property verts associated with a single geometric vertex, allowing sudden property changes, e.g. at Boolean intersections, without sacrificing manifoldness.

    Manifolds also keep track of their relationships to their inputs, via OriginalIDs and the faceIDs and transforms accessible through MeshGL. This allows object-level properties to be re-associated with the output after many operations, particularly useful for materials. Since separate object's properties are not mixed, there is no requirement that channels have consistent meaning between different inputs.

    Input & Output

    MeshOptions
    Mesh

    An alternative to Mesh for output suitable for pushing into graphics libraries directly. This may not be manifold since the verts are duplicated along property boundaries that do not match. The additional merge vectors store this missing information, allowing the manifold to be reconstructed.

    forDivisions

    Returns a quality that makes Manifold.revolve divide the given angle into exactly this many divisions. Like revolve, it uses the angle's magnitude, clamped to 360 degrees. A revolve of more than 120 degrees needs at least two divisions, and of more than 240 degrees at least three, and a tiny angle cannot get more divisions than the largest int count allows. Past those limits it returns the closest count revolve allows. A non-finite or zero angle, which revolve rejects, gives the default quality.

    CircularQuality

    Controls how circular shapes are quantized on construction. A number sets segments. Missing fields use their defaults.

    If segments is greater than two (for a sphere, positive), it takes precedence. Otherwise the minimum is used of the segments calculated based on edge length and angle, rounded up to the nearest multiple of four.

    • segments: Number of segments in a full 360-degree circle, the same as passing a number. Partial revolves use the matching fraction of it, rounded up, ignoring an excess of one unit in the last place so floating-point error cannot add a division. A sphere rounds it up to a multiple of four. Default is 0, meaning no constraint is applied.
    • minAngle: Minimum angle in degrees between consecutive segments. Default is 10.
    • minEdgeLength: Minimum length of segments. Default is 1.
